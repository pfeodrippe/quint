# Foreign bindings

Quint can bind **declaration-only** operators to host implementations loaded by the TypeScript evaluator.

This feature is currently:

1. **Bun-only** at runtime
2. available only through the **TypeScript** backend
3. limited to **synchronous** `pure def` and `pure val` declarations

## Declaring a foreign operator

Declare the operator in Quint without a body and with a full type annotation:

```quint
module foreignModule {
  pure def add1(x: int): int
  pure val answer: int
}
```

If a declaration-only operator is evaluated without a matching binding, Quint fails explicitly.

## CLI usage

Pass a bindings file with `--foreign-bindings`:

```sh
bun ./dist/src/cli.js run \
  --backend=typescript \
  --foreign-bindings ./bindings.json \
  ./spec.qnt
```

The same flag is available on:

1. `quint run`
2. `quint test`
3. `quint repl`

## Binding file format

```json
{
  "bindings": [
    {
      "kind": "module",
      "module": "foreignModule",
      "name": "add1",
      "path": "./module-impl.cjs"
    }
  ]
}
```

Each binding must point at a declaration-only `pure def` or `pure val` in the named Quint module.

## `module` bindings

`module` bindings are the simplest path. Quint loads a JS/TS module in-process and calls an exported function directly.

Example host module:

```js
module.exports = {
  add1(x) {
    return { '#bigint': (BigInt(x['#bigint']) + 1n).toString() }
  },
}
```

Arguments and results use the same ITF-shaped JSON values that Quint already uses for traces:

| Quint value | Host value |
| --- | --- |
| `42` | `{ "#bigint": "42" }` |
| `"hi"` | `"hi"` |
| `true` | `true` |
| `(1, 2)` | `{ "#tup": [{ "#bigint": "1" }, { "#bigint": "2" }] }` |
| `Set(1, 2)` | `{ "#set": [{ "#bigint": "1" }, { "#bigint": "2" }] }` |

## `ffi` bindings

`ffi` bindings use Bun's `bun:ffi` support to call a symbol from a native shared library.

```json
{
  "kind": "ffi",
  "module": "foreignModule",
  "name": "add1",
  "library": "./libforeign.dylib",
  "symbol": "add1_host"
}
```

Current fast native ABI contract:

1. Quint infers the native signature from the declaration's type annotation.
2. The native ABI currently supports only primitive Quint types:
   - `int` -> `i64`
   - `bool` -> `bool`
   - `str` -> `cstring`
3. Non-primitive FFI signatures are rejected explicitly.
4. `freeSymbol` is optional and only valid when the result type is `str`.

That makes the native side straightforward for Rust, Zig, or C shims:

```rust
#[unsafe(no_mangle)]
pub unsafe extern "C" fn add1_host(value: i64) -> i64 {
  value + 1
}
```

If a string-returning symbol allocates a C string, you may also provide `freeSymbol` so Quint can release the returned pointer after decoding it.

## `wasm` bindings

`wasm` bindings load a Bun-resolved Wasm module and call one exported function.

```json
{
  "kind": "wasm",
  "module": "foreignModule",
  "name": "add1",
  "path": "./module.wasm",
  "export": "add1"
}
```

Current contract:

1. Quint loads the module through Bun's Wasm/module loader.
2. The selected export must be callable from JavaScript.
3. Arguments/results still use ITF-shaped JS values.

For non-trivial Wasm toolchains, that usually means using JS-visible glue generated by the toolchain or a thin wrapper layer that exposes a callable export with Quint's value contract.

## Current limitations

1. Foreign bindings are rejected on the Rust backend.
2. Async host functions are rejected.
3. Only declaration-only `pure def` and `pure val` targets are supported.
4. There is no subprocess fallback path.
5. Invalid bindings and invalid host return values fail explicitly.
6. A checked-in stress script is available via `npm run bun-foreign-stress` to compare native-override timing against an equivalent pure Quint operator.
